# JdbcCDC 同步后表名为什么是 s_dwd_dnl_dwd_jld_fn_cat_dim 而不是 dwd_jld_fn_cat_dim

- 时间：2026-11-06 16:50
- 问题类型：Flink CDC 数据同步（行为分析）
- 涉及入口：`org.apache.flink.lakesoul.entry.JdbcCDC`（postgres 分支）

## 结论（先行）

表名带 `s_` 前缀并拼接 schema 名，是 `BinarySourceRecord.fromMysqlSourceRecord` 中**硬编码的命名规则**，不是参数没生效。当前代码没有任何参数可以让目标表名等于原始表名 `dwd_jld_fn_cat_dim`。

## 你的参数实际效果

| 参数 | 是否被识别 | 说明 |
|---|---|---|
| `--source_db.schema_tables "dwd_dnl.dwd_jld_fn_cat_dim"` | 生效 | 决定 PG 侧抓取 schema=`dwd_dnl`、表=`dwd_jld_fn_cat_dim` |
| `--sink_db_name dwd_dnl` | 生效 | 目标 namespace = `dwd_dnl`，同时参与表名拼接 |
| `--naming.enable true` / `--naming.target_namespace dwd_dnl` | **无效** | 全代码库搜索不存在这两个配置项，ParameterTool 静默忽略 |
| `--source_db.slot_name dwd_jld_fn_cat_dim` | 生效 | 仅作 PG 复制槽名，与表名无关 |

## 表名生成逻辑（代码依据）

[BinarySourceRecord.java](file:///e:/workspace/workspace/LakeSoul/lakesoul-flink/src/main/java/org/apache/flink/lakesoul/types/BinarySourceRecord.java#L64-L82)：

```java
// L69: 从 debezium topic 解析出源表 TableId，如 dwd_dnl.dwd_jld_fn_cat_dim
TableId tableId = new TableId(io.debezium.relational.TableId.parse(sourceRecord.topic()).toLowercase());
// L70: sourceSchemaName = "dwd_dnl"
String sourceSchemaName = tableId.schema() == null ? tableId.catalog() : tableId.schema();

// L73-82: 命名规则
if (sinkDBName.equals(sourceSchemaName)) {                       // 你的情况：dwd_dnl == dwd_dnl，走这里
    tableName = String.format("s_%s_%s", sourceSchemaName, tableId.table());  // s_dwd_dnl_dwd_jld_fn_cat_dim
} else {
    tableName = String.format("s_%s_%s_%s", sinkDBName, sourceSchemaName, tableId.table());
}
```

代入你的参数：

- `sinkDBName` = `dwd_dnl`（来自 `--sink_db_name`）
- `sourceSchemaName` = `dwd_dnl`（来自 PG 表的 schema）
- 两者相等 → 走第一个分支 → 表名 = `s_` + `dwd_dnl` + `_` + `dwd_jld_fn_cat_dim` = **`s_dwd_dnl_dwd_jld_fn_cat_dim`**

即使 `--sink_db_name` 与源 schema 不同（走 else 分支），表名也会是 `s_<sink库>_<schema>_<表名>`，依然带 `s_` 前缀。两条分支都不存在输出裸表名的路径。

## 设计意图（推测）

`s_` 前缀 + schema 拼接是为了**整库/多 schema 同步时避免目标表名冲突**（不同源 schema 下可能有同名表），并标识该表来自同步（sync）任务。
