# SyncDatabase 出湖能否同时指定多张表分析

- 分析时间：2026-11-04 13:44
- 问题分类：出湖任务 / SyncDatabase
- 涉及代码：`lakesoul-flink/src/main/java/org/apache/flink/lakesoul/entry/SyncDatabase.java`

## 一、结论

**不能。** `SyncDatabase` 一个任务只能处理「一张源表 → 一张目标表」，没有多表参数、没有逗号分隔解析，也没有循环编排逻辑。多张表需要提交多个任务（或改用其他方式）。

## 二、现状代码分析

1. **参数读取为单值**（SyncDatabase.java:67-71）：
   ```java
   sourceDatabase = parameter.get(SOURCE_DB_DB_NAME.key());
   sourceTableName = parameter.get(SOURCE_DB_LAKESOUL_TABLE.key()).toLowerCase();
   targetDatabase = parameter.get(TARGET_DB_DB_NAME.key());
   targetTableName = parameter.get(TARGET_DB_TABLE_NAME.key()).toLowerCase();
   ```
   `source_db.table_name`、`target_db.table_name` 均为单个字符串，无 `split(",")` 之类的多表解析。

2. **执行路径为单表**：`xsyncToPg` / `xsyncToMysql` / `xsyncToDoris` / `xsyncToMongodb` / `xsyncToSqlServer` 每个方法只构建一个 sink DDL、执行一条 `insert into <target> select * from lakeSoul.<db>.<table>`。

3. **对比入湖入口**：`JdbcCDC`、`OracleCdc`、`MysqlCdc`、`JdbcIngest` 等入湖（CDC）入口均支持 `source_db.schema_tables` 逗号分隔多表 + `LakeSoulMultiTableSinkStreamBuilder` 多表 sink；而出湖方向（`SyncDatabase`）没有对应的多表实现。

4. **文档佐证**：`14-export-to-databases.md` 中 `--source_db.table_name`、`--target_db.table_name` 描述均为单个表名，无多表说明。

## 三、不改代码的变通方案

### 方案 A：每张表提交一个任务（当前推荐）

- 每张表启动一个 `SyncDatabase` 任务，各自独立的 checkpoint/并行度；
- 缺点：表数量多时任务数量膨胀，管理成本高，每个任务独占 JobManager 资源开销。

### 方案 B：改用 Flink SQL 自行编排

- 绕过 `SyncDatabase`，用 Flink SQL Client / SQL Gateway 注册 LakeSoul Catalog + JDBC Catalog，自行编写多条 `insert into` 语句（可用 `StatementSet` 合并为一个 job 提交）；
- 可获得「单 job 多表」效果，但需要用户自行编写建表 DDL 和 insert 语句，失去 `SyncDatabase` 的自动建表/类型映射便利。

## 四、如需正式支持（改代码方案）

支持「单任务多表出湖」，改动点：

1. **参数解析**：`source_db.table_name`、`target_db.table_name` 支持逗号分隔（或新增 `source_db.schema_tables` 风格参数），源表数量与目标表数量需一一对应；
2. **循环编排**：在 `main` 中按表循环执行「建目标表 DDL → 注册 sink 表 → 收集 insert 语句」；
3. **单 job 提交**：用 `StreamStatementSet` 收集所有 `insert into`，最后统一 `execute()`，避免每条 insert 各自触发一个 job（注意当前 PG/MySQL 路径用的是 `tEnvs.executeSql(insert)`，会立即触发执行，需改造）；
4. **类型映射与主键**：每张表独立获取 schema 和主键（`getTablePk` 按表名查询，逻辑本身支持）；
5. **血缘**：`LakeSoulInAndOutputJobListener` 需支持多 input/output facets 上报；
6. **失败语义**：多表共用一个 job 后，任一表 sink 失败会导致整个 job 重启，需明确是否接受；若需隔离，仍应推荐方案 A 多任务。

## 五、风险与注意事项

- 多表同 job 共享 checkpoint 与 sink 并行度，最慢的表会拖慢整体 checkpoint 间隔；
- 逗号分隔参数需要与表名中可能的特殊字符做转义约定；
- 批量模式（`use_batch=true`）下多表串行执行与并行执行的行为需定义清楚。
