## 3. 根因推断

`ocrpersoninfo:0` 只有约 1 万行，正常几秒可读完，却 24+ 分钟未完成，可能原因：

1. **该表含大字段**（OCR 人员信息表通常存身份证照片/人脸图片等 BLOB/MEDIUMTEXT），
   单行数据量大，JDBC fetch 慢或触发 MySQL 侧慢查询；
2. **TaskManager 侧卡住**：GC/OOM、反压（sink 写入 LakeSoul/S3 慢导致 source 反压）；
3. **MySQL 侧查询被阻塞**：如 MDL 锁等待、长事务导致快照查询 hang 住。

注意：本日志是 **JobManager 日志**，快照数据的实际读取发生在 TaskManager 的
split reader 线程中，卡住的直接原因需要 **TaskManager 日志**确认。

- 已完成的约 59 张表数据正常同步（每 10s checkpoint 正常提交到 S3）。
